# 3.0 第二轮（P1 角色绑定 + M1 配置中心）调查摘要

来源：2026-10-17 只读调查（themis-3.0 分支 HEAD `b5e9ea5`），供第二轮 2gate 设计引用；行号以写设计时重新核对为准。PD = `scripts/pi_dispatch.py`，KC = `scripts/kit_config.py`，CP = `scripts/codekit/config_profiles.py`，A2 = `scripts/codekit/adapters/second_cli.py`，AH = `.../adapters/heterogeneous.py`，AC = `.../adapters/capability.py`。

## 关键结论

1. **现有离线适配器层接不进 Pi 当执行端**：
   - `check_role_gate` 对非只读的执行端 profile 返回 EXECUTOR_SCOPE_UNKNOWN（AH:619–620）；
   - `evaluate_start_gate` 要求 `invocation.read_only is True`（AH:792–795）；
   - `SecondCliProfile` 缺省只读、`validate_profile` 强制只读（A2:123、434–435），`session_id` 必填（A2:184–185），而 Pi 用 `--no-session`；
   - facade 的 `probe` 缺省可执行文件是 `claude`（AH:28）。
   第二轮要先重定适配器的执行端准入模型，再谈抽 Pi。
2. **v3 配置文件今天会被 kit_config 整体拒绝**：`schema_version`、`runtimes`、`profiles`、`roles`、`presets` 等都是未知键（KC:259–260）；`split_path` 最多两层（KC:347），`roles.contract.profile` 这类路径写不进；`show` 的 KEYS 顺序被测试钉住（TD:2743）。
3. **CP（config_profiles）与设计 §6.3 的形状不一致**：凭据字段是 `credential_refs` 不是 `credential_env`（CP:344–347）；`allowed_models` 是对象不是 `"provider/id"` 字符串（CP:429–439）；`independence` 等策略键是 E_CFG_POLICY（CP:424–427）；`presets`、`feedback`、`logging`、`ui` 是未知字段（CP:378–380）；新角色名是 E_CFG_SCHEMA（CP:396）；只认 schema_version 2；`PLACEHOLDER_RE` 只认 `EXACT_MODEL_ID`（CP:24）。CP 只依赖标准库（CP:11–19），目前只有两个测试文件导入它。
4. **没有 `.agent/dispatch.local.json` 的读取代码**；`Repo.config()` 用宽松的 `json.load`、忽略未知键（PD:1145–1155）。
5. **合同的 executor 块目前是权威**：`resolve_executor`（PD:3265–3296）读合同、`PI_EXEC_*` 只补缺、`allowed_executors` 只在非空时检查；每个 attempt 的快照是 `executor.json`（PD:4371）；`meta.json` 没有配置快照或绑定哈希。第二轮要定合同与 `roles.execution` 谁优先。
6. **doctor 与 preflight 有三处不一致**：auth check 是否带 `--no-refresh`（PD:6977 对 2586）、是否无条件执行 auth（6976 对 2585）、是否总要求 `--no-context-files`（6951 对 2554）。设计 §7.1 写的是 `--no-refresh`。
7. `DEFAULT_ENV_REMOVE` 会移除 `CLAUDE_CODE_OAUTH_TOKEN`（PD:127）：用 Claude Code 当执行端时会把它自己的登录去掉，要按适配器区分。

## Pi 绑定点（按建议的修改顺序）

1. 适配器层的执行端准入模型（见关键结论 1），并补 `list_models`、`auth_readiness`、`render_role_input`。
2. 进程运行与提示的交付方式：`run_supervised` 固定 `stdin=DEVNULL`（PD:825–836）；Pi 用 `@file` 附件（PD:4343–4346、4375–4378）；A2 的提示走 stdin、超时写死 900（A2:454）。
3. 导入与保护：导入 `codekit.adapters` 会连带导入约七个模块（adapters/__init__.py:3–12）；`KIT_LOADED_FILES`、import 扫描（TK280:126–139 不跟随包与 `..` 相对导入）、kit_install 清单要同步；本仓库 `extra_protected_paths` 含 `scripts/codekit/**`、`schemas/**`。
4. 叶子解析器变成适配器方法：`parse_help`（PD:2388–2399）；`list_models_rows` / `list_models_empty_reason`（PD:2402–2424）→ `list_models`；auth check（PD:2584–2592 对 6975–6981）→ `auth_readiness`（TLE:262–263 钉住了不带 `--no-refresh`）。
5. 预检变成 `probe` + `validate_profile` + 能力记录：`pi_preflight`（PD:2542–2596）、`REQUIRED_PI_FLAGS` / `RESOURCE_FLAGS`（PD:73–74）、版本门槛（PD:54、4284–4286、4498–4503）、上下文发现（PD:2326–2385）。
6. argv 与环境构造变成 `build_invocation`：`cmd_run`（PD:4337–4347）、`cmd_smoke`（PD:7358–7366）；`resolve_pi_command` / `PI_DISPATCH_PI_CMD` / `ensure_argv_safe`（PD:2288–2323）改为 runtime 的 `command` 加本机覆盖；测试经环境变量接线（TD:29、legacy_harness:457）。
7. 事件标准化：把 `summarize_events` 拆成 Pi 协议解析（PD:2739–2873、2886–2932）→ `normalize_event` / `collect_result`，与内核审计（可疑命令、临时路径、越界路径、解读线索、模型核对，PD:2787–2855 等）在标准化事件上运行；另有 `_run_health_state`（PD:3854–3905）、`_live_progress` 按紧凑 JSON 的字节标记计数（PD:6716–6719）、用量键名（PD:2603–2621、1177）、bash / powershell 工具名假设（PD:1820、2784、3376、3414–3424、5761）。
8. 执行端解析与角色绑定：`resolve_executor` + `PI_EXEC_*` + `allowed_executors`（PD:3265–3296）；合同 executor 的 schema（PD:1439、1809–1823）、Identity 行（PD:1647–1650、1934–1939）、`executor.json`（PD:4371）。
9. 配置文件：KC 的 KEYS、`validate_config`、`split_path`、`show`（KC:200–271、344–409）；`write_config` 固定临时文件名、无历史，`cmd_init` 绕过 `write_checked`（KC:327–334、480–483）；PD 宽松的 `Repo.config()`；CP 只认 v2；没有 local 覆盖的读取。
10. 测试钉住的 Pi 品牌输出：分支前缀 `pi/`（PD:5934–5935，TD:275）、尾注 `Pi-Executor:`（PD:5953–5955，TD:665）、提交主题“Pi 候选”（PD:1633，TD:278）、证据文件名 `pi-help.txt` 等（PD:2549–2595、4327）、摘要与 G1 文字“Pi 退出码”（PD:3502、5736）、执行说明“你是本任务的 Pi 执行器”（PD:3310）、`.pi/**` 保护（PD:101、2332）。

## 测试接线

- `tests/stub_pi.py` 不检查 argv 标志，只读 `--provider` / `--model` / `--thinking` 与 `@` 文件；场景见其文档串。
- `tests/test_dispatch.py` 是脚本式运行器（`check()` 追加结果），经 `PI_DISPATCH_PI_CMD` 指向 stub（TD:29），**没有设置 `PI_CODING_AGENT_DIR`**，所以会读到本机真实的 `~/.pi/agent`。
- `tests/legacy_harness.py` 生成另一个假 Pi 并记录 argv，隔离环境设置 `PI_DISPATCH_PI_CMD` 与 `PI_CODING_AGENT_DIR`；`tests/test_legacy_events.py` 钉住预检的 argv。
