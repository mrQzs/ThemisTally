# 3.0 首轮实测记录

设计：`docs/themis-tally-3.0-r1-日志与插件管理.md` 第 5 节；上位设计 `docs/themis-tally-3.0-四端分层解耦架构.md` 第 13 节。

## 口径

- 本轮比较的是“谁把一份已批准的设计展开成合同与 oracle”（A 组：规划端子代理；B 组：Pi 作为合同端），不是“从概要步骤到合同”。2gate 已经为两组都产出了经审核的详细设计。
- 规划端的每个阶段都在新的子代理里做（与主会话同一模型），两组的子代理依次运行、时间窗口不重叠；用量取子代理结果里报告的数字与它的会话记录。
- Pi 的用量取各 attempt 的 `events-summary.json`；`bb/step-5-preview` 没有带来源的单价，只报 token（用户决定）。
- 规划端用量只覆盖会话记录里有的调用，advisor 等不写进会话记录的调用不在其中，是下界。
- 两个任务不同，只能看量级与质量信号，不能当作严格对照。

## 环境备注

- 本机 `python` 指向 conda 环境 `cell_gpu`（3.10.19），其 site-packages 里有一个名为 `tests` 的第三方包，会遮住仓库的 `tests/`（README 已提示）。依赖 `from tests.… import` 的旧测试在这个解释器下收集失败。全量测试改用 `C:\Users\<用户>\miniconda3\python`（3.13.16，`tests` 解析到仓库）。合同里的检查只跑具体的测试文件（它们经 `sys.path` 导入模块），不受影响。

### 偏离与发现

- **子代理的模型不是主会话的模型**：设计写“与本会话同一模型”，实际 T1 规划子代理跑在 `claude-haiku-5-5` 上（本环境子代理的缺省模型）。A 组因此实际是“Haiku 写合同与 oracle”，不是“高能力规划端写”。后续 B 组的规划审核步骤显式指定模型，并在下表注明。
- **子代理会话记录的写法**：同一回复先写中间记录（`stop_reason` 为 null，`output_tokens` 未到终值），最后一条才是最终记录。按“同 id 用量必须一致”去重会把 40 个 id 里的 33 个判为冲突，按“取第一条”会把 output 算成 2,467（实为 299,445）。设计 D4 已改为只比较最终记录（§0 impl-3），并补送闸一第 4 轮。
- **规划端子代理的结论需要核对**：它报告“缺 `allowed_executors` 时调度器拒绝任何执行器”，核对代码不成立（`pi_dispatch.py:3285-3295`，列表为空时不限制）；报告“`integrate` 需要 `local_branch` 授权”成立（`pi_dispatch.py:6376`）。
