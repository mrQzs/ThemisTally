# 06 插件定义与锁定

本文是拟议实施说明，尚未实现，也不是已审核、可派遣的任务合同。
总设计：[Code-Kit v2 设计](../themis-tally-v2-design.md)；实施索引：[README](README.md)。
本模块完成后，调度器能够识别、校验和锁定受信任的声明式任务插件。

## 1. 目标与非目标

- 定义任务插件 manifest、输入输出类型、资源清单和依赖关系。
- 在派遣前发现插件版本、平台、能力、资源路径和权限需求问题。
- 将实际采用的全部插件内容锁定，使同一合同可复核其输入。
- 区分任务插件、runtime adapter 和 host adapter，避免混用加载机制。
- 首期只支持仓库内明确启用的声明式插件；不自动扫描用户目录或网络市场。
- 不开放任意 Python/JavaScript 插件代码在调度器进程内执行。
- 不替换 G0–G6、独立验收、候选快照、保护路径和用户授权。

## 2. 依赖与输入输出

前置依赖：[02 配置](02-config-and-profiles-审阅增强版.md)、[03 审核与锁定](03-approvals-and-locks-审阅增强版.md)、[05 平台执行](05-cross-platform-runtime-审阅增强版.md)。
03 的审核机制仅接收通用资源引用；本模块向它提供插件锁引用，不反向要求 03 认识插件字段。

| 方向 | 内容 | 所有者 |
|---|---|---|
| 输入 | 配置中显式启用的插件 ID、版本和项目策略 | 配置模块 |
| 输入 | manifest、schema、模板、资源文件与平台检查定义 | 受信任插件目录 |
| 输入 | 角色能力、目标平台和已有授权 | 配置、适配器与主模型 |
| 输出 | 解析完成的插件集合、问题清单、资源清单 | 插件模块 |
| 输出 | `.agent/plugins.lock.json` 与其文件哈希 | 调度器 |
| 输出 | 可供工作流消费的类型、步骤和检查定义 | 工作流模块 |

公共引用采用 `ResourceRef={kind,id,sha256}`；需要定位文件时增加仓库相对 `path`。
锁引用的哈希取具体锁文件字节，不另设 JSON 规范化算法，也不把锁文件自身的哈希写入自身。
插件文件条目分别记录文件字节哈希；审核同时绑定整个锁文件的 `ResourceRef`。

## 3. 现状与复用点

- 当前尚无 `plugins/`、`workflows/` 任务插件体系，本模块属于新增能力。
- `scripts/pi_dispatch.py::RESOURCE_FLAGS` 默认关闭 Pi 扩展、技能和模板自动发现，继续保留此约束。
- 复用既有合同范围、保护路径和授权校验，不由插件重做一套较宽松规则。
- 复用 05 的结构化命令与平台选择，不让插件自行拼接通用 shell 字符串。
- 复用 03 的审核失效规则；插件改变与配置改变一样，是输入变化。
- 首批插件资源由调度器显式编译进角色请求；它们不是 Pi 原生扩展或 Codex 插件包。

## 4. 接口和行为约束

### 4.1 Manifest 最小内容

| 字段组 | 拟议内容 | 校验要求 |
|---|---|---|
| 身份 | `id`、`version`、`api_version`、`type` | ID 唯一；版本显式；首期类型为 task |
| 兼容 | `platforms`、角色、所需 runtime 能力 | 平台仅用 `linux/macos/windows`；不推测 CLI 能力 |
| 数据 | 输入 schema、输出 schema、步骤 | 引用存在；必要字段明确；输出类型可识别 |
| 检查 | 检查模板与平台实现 | 每个声明支持的平台都有可用实现 |
| 资源 | 相对路径及用途 | 内容可锁定；拒绝绝对路径、穿越和越界链接 |
| 组合 | 依赖、互斥项、权限需求 | 无环、无同 ID 冲突；权限只能提出需求 |

字段的最终 JSON schema 在实现时落盘；样例不能代替 schema，未知字段应明确拒绝。下划线说明字段例外仅用于 02 的配置，不适用于插件 manifest。
首期依赖采用精确版本，避免引入远程版本求解器；后续支持版本范围时须另定选择与锁定规则。
资源路径相对于插件根目录解释；解析实际文件后再次确认仍位于该目录。
插件目录内的符号链接或 Windows junction 不能绕过边界检查。

### 4.2 内容锁定

1. 从启用列表解析传递依赖，并检查 ID、版本和 API 兼容性。
2. 收集 manifest 及实际使用的 schema、模板、检查定义和资源，逐文件计算哈希。
3. 生成确定的条目顺序和完整文件清单，写入插件锁文件。
4. 待审合同或请求的生成方在冻结字节前纳入插件锁引用；03 只核验并登记对应 `input_refs`，不回填已审核合同。
5. prepare/run 重新核对所需内容；任一文件变化、缺失或新增加载项均拒绝沿用旧审核。

锁定对象是完整的实际输入，不仅是 manifest 的版本字符串。
修改后的内容不能冒充同版本已审核内容；即使版本未变，哈希变化也必须重新审核。
锁文件由调度器生成；planner 或插件输出的 `locked: true` 不构成锁定证据。
生成新锁不改写历史 attempt 中保存的旧锁与引用。

### 4.3 权限与检查边界

有效权限取现有用户授权、项目策略、角色允许集合、合同授权的交集。
插件声明只能用于检查“需要什么”，不能赋予安装、联网、提交或访问外部路径的权限。
缺权限时返回具体缺口；由主模型缩小任务或依据既有授权处理，不能自动提权。
检查模板只是待审核输入，正式合同锁定相应命令后才可由核心 runner 执行。
插件不得声明直接 PASS、关闭核心门禁、覆盖同名核心检查或修改原始证据。
新增可执行扩展需另行设计维护路径，不能从本模块的声明式字段暗中装载代码。

## 5. 预计文件范围

- 新增 `scripts/codekit/plugins.py`：解析、依赖校验、资源边界与内容清单。
- 新增任务插件 schema 与最小合法/非法 fixture，具体目录遵循 01 的协议布局。
- 新增 `plugins/` 示例插件；首批真实业务插件留给 08。
- 接入 02 配置、03 通用审核输入、05 平台检查和既有 prepare/run 门禁。
- 新增插件单元测试与端到端 fixture；不直接修改 `.agent/runs/` 历史证据。
- `.agent/plugins.lock.json` 是将来在目标项目中生成的产物，本次拆分不创建实际锁。

涉及调度核心和保护路径的改造由主模型按实施授权处理；普通 Pi 执行器禁区不因本说明而改变。

## 6. 实施步骤

1. 冻结 manifest schema、精确版本规则和 `ResourceRef` 接口，先建立有效/无效样本。
2. 实现纯解析、依赖图和路径边界校验，错误指出插件、字段和依赖链。
3. 实现文件清单与锁文件写入，明确文件缺失、读取失败和并发更新的失败行为。
4. 将平台、能力与权限需求接入现有预检，保留分项错误，不在预检时运行插件命令。
5. 接入审核输入及 prepare/run 的漂移检查，确保调用任一路径都不能漏掉门禁。
6. 用本地 fixture 验证组合与篡改场景，再交 07/08 消费公开接口。

## 7. 验收标准

- **06-A01**：合法插件解析成功；缺字段、未知 API、重复 ID 和版本冲突均给出明确错误。
- **06-A02**：缺依赖、循环和互斥插件不能生成可派遣组合；错误包含相关插件链。
- **06-A03**：绝对路径、`..` 穿越及解析后越界的链接被拒绝；正常子目录资源可用。
- **06-A04**：模板、schema 或检查文件只改一字节，也使相关锁验证失败；manifest 未变不能掩盖漂移。
- **06-A05**：目标平台或角色能力缺失时阻塞；不能静默跳过检查或切换 CLI/profile。
- **06-A06**：插件请求新增权限不能提升有效权限；伪 PASS、门禁覆盖和证据写入声明均被拒绝。
- **06-A07**：两个插件提供同名资源时显式报冲突或使用声明的命名空间，不按加载顺序覆盖。
- **06-A08**：未启用插件的旧 Pi fixture 保持原行为；历史 attempt 的字节和哈希不被重写。
- **06-A09**：锁文件引用与 03 的通用 `input_refs` 兼容；审核后修改插件内容会阻止 prepare/run。

## 8. 兼容与恢复

v1 合同继续按原 schema 和 Pi 路径执行，不追补历史插件锁，也不宣称具备 v2 插件保证。
v2 插件流程必须具备相应审核与锁，不能删掉字段降级为 v1 来继续运行。
锁生成中断时保留旧有效锁；半成品不成为当前锁。新锁写入后，依赖旧内容的审核保持可追溯。
发现漂移时重新解析、生成锁并审核新版本，不就地修补已派遣合同或 attempt。
卸载插件前检查未完成任务引用；不能删除仍需复审的证据或保存的输入快照。

## 9. 后续合同拆分建议

以下是可供后续规划的小工作包，不是派遣合同；届时逐包绑定实际基线、范围、预算与授权。

1. manifest/schema 与依赖校验：只做纯解析，交付 fixture 和错误分类。
2. 资源边界与内容锁：交付完整内容清单、锁文件和漂移检测。
3. 预检及审核集成：接入能力、平台、权限和 prepare/run，补防绕过场景。
