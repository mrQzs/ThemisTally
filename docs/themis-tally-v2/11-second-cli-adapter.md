# 11 第二种真实 CLI 接入

状态：拟议实施说明，尚未实现；本文件不是已审核或可直接派遣的任务合同。
上位设计：[总设计](../themis-tally-v2-design.md)第 4.3、10 节；导航：[实施索引](README.md)。
本模块验证多 CLI 解耦是否成立，不预先指定第二 CLI 的品牌、版本或默认模型。

## 1. 目标与非目标

用第二种真实 CLI 接入规划或执行角色，证明调度核心不依赖 Pi 的命令与事件格式。
通过不同 runtime/profile 绑定，让规划 CLI 与执行 CLI 可独立选择。
可支持能力范围必须由真实版本、协议和运行证据说明，不能把适配器类存在当成接入完成。

- 包含：CLI 选择条件、协议调查、适配器、能力声明、离线夹具及获授权的真实验证。
- 包含：真实返回的模型、结束、工具和用量证据与调度器事件的映射。
- 不包含：在本文中猜测厂商参数、安装/升级依赖或读取凭据内容。
- 不包含：为通过验收关闭 G1、范围检查、独立检查或原始证据保留。
- 不要求每个 CLI 都支持每个角色；但局部支持不能冒称完整异构链路已完成。

## 2. 依赖与输入输出

| 输入 | 输出 |

| 候选 CLI、目标平台和所需角色清单 | 选择理由、能力缺口及可接受用途 |
| 本机真实版本/help、官方协议资料与脱敏样本 | 有来源的版本/能力报告及测试夹具 |

## 3. 现状与复用点

当前 `resolve_pi_command` 处理 Pi 命令定位，`pi_preflight` 核验 Pi 参数与模型。
`summarize_events` 依赖 Pi 的会话、消息、工具和结束事件，不能用于直接解释另一 CLI。
`RESOURCE_FLAGS` 控制 Pi 资源自动加载；第二 CLI 要实现等效的可控上下文并记录差异。
`tests/stub_pi.py` 与 `stub_pi_help.txt` 提供现有 Pi 离线测试基础，不证明第二 CLI 能力。
进程监督、候选快照、范围核对、独立检查和门禁继续由公共核心承担。

适配器负责 CLI 协议差异，平台 runner 负责 shell/进程差异，避免两者重复建立启动逻辑。
实施调查前不宣称某 CLI 具有只读模式、完整工具审计或可核验的实际模型标识。

## 4. 接口和行为约束

### 4.1 选择与能力矩阵

候选应具备可脚本调用的稳定入口、可识别版本、结构化结果，以及至少一个角色所需的证据能力。
选择时比较实际可用平台、参数/输入协议、模型选择、会话隔离、结束事件与错误行为。
仅记录认证是否就绪的脱敏结果，不查阅、输出或复制密钥值，不以认证缺失触发自动换模型。

| 能力 | 规划角色 | 执行角色 |
|---|---|---|
| 明确角色输入与结构化输出 | 必须能提取并校验 PlanningBundle | 必须能提取报告并关联候选 |
| 模型身份 | 按角色证据要求记录，缺失明示 | 维持 G1；实际模型缺失/不符不能正常通过 |
| 结束与错误证据 | 能判断 bundle 是否完整 | 能判断任务结束及工具是否仍待完成 |
| 工具审计与范围 | 按调查权限和已声明证据等级预检 | 满足所选工作流的审计要求 |
| 只读能力 | 说明真实约束及其限制 | 不用只读声明代替执行范围检查 |
| 用量 | 可未知但不能冒充零 | 可未知但需保留可观测预算限制 |

缺少某角色的必要能力时在预检阻塞该用途；可缩小支持范围，但需主模型接受并如实标注。
另一 CLI 已支持 planner 不代表它已支持 executor；同一 CLI 的不同版本也分别核验。

### 4.2 适配器实现

实现公共 `probe`、`validate_profile`、`build_invocation`、`normalize_event`、`collect_result` 接口。
模型 provider 是否必需、思考参数取值和工具名称映射由该适配器 schema 明确。
核心不得要求所有 CLI 接受 Pi 的 `--thinking high` 或 Pi 事件字段。
启动输出 argv、stdin/请求文件、cwd、必要环境变量名称；路径与 shell 交由模块 05 处理。
隔离规划与执行会话，禁止沿用 CLI 默认历史会话来隐式携带旧规则或额外授权。
资源自动发现、系统提示和扩展加载能力须声明；无法控制的部分形成明确限制。

统一事件保存 `request_id`、`run_id`、`seq`、role、类型、payload 与原始记录引用，复用模块 01 协议。
资源引用复用 `ResourceRef = {kind, id, sha256}`；文件另含仓库相对 `path`。
`sha256` 锁定具体 UTF-8 文件字节，原始脱敏保留流与标准化事件均需可定位。
未知、截断、畸形或未结束事件不能被丢弃后伪装成完整成功；处理策略须可测试。
配置请求模型、CLI 回报模型和提供商回报分别记录，不用请求参数替代实际证据。
实际退出码、协议完整性、报告完整性和验收结论独立记录，进程退出零不自动 PASS。

### 4.3 异构运行与预算

配置示例只使用占位 runtime/profile；选定品牌和精确模型后再写入获授权配置。
用“规划 runtime A、执行 runtime B”作为必测组合，两个角色的环境锁分别保存。
若支持反向组合，另做独立验证，不能由正向结果推断；同 CLI 双 profile 也单独标记。
所有调用沿用全局 `request_id`，规划修复、执行返工和工具审阅不能重置累计预算。
用量未回报写 `unknown`；没有提供商硬限额时，不把本地估算宣传为费用硬上限。

## 5. 预计文件范围

- 新增 `scripts/codekit/adapters/` 下第二 CLI 实现及适配器 schema。
- 通过已定义的注册接口启用适配器，不在核心运行路径新增品牌分支。
- 新增脱敏协议夹具、适配器协议测试和跨 CLI 集成测试。
- 更新配置示例、CLI 能力矩阵、环境核验说明和版本兼容记录。
- 如需调整公共协议，先修订模块 01/04 的设计与验收，不能仅为该 CLI 绕过约束。

新增适配器代码属于受信任核心变更；真实配置与依赖变化另按现有授权规则处理。
调查记录只保存必要版本和协议证据，不保存凭据、完整环境变量或无关工作目录信息。

## 6. 实施步骤

1. 主模型据目标平台与角色需求选候选，写清选择条件和尚未证实的能力。
2. 在实施环境核对真实版本/help 与官方文档，建立逐项能力证据，不猜参数。
3. 实现适配器并使用脱敏样本/离线 stub 覆盖成功、缺证据、异常和取消路径。
4. 经过授权后执行最小真实调用，核对协议与夹具差异，锁定可支持版本范围。
5. 接入模块 09，完成 A 规划、B 执行、主模型审核与独立验收的代表性任务。
6. 汇总实测平台/角色组合和限制；无法满足必要证据则保留部分支持并报告未完成项。

## 7. 验收标准

| 编号 | 场景与通过条件 |
|---|---|
| 11-A01 | 新适配器经注册和配置接入，调度核心无需新增厂商品牌分支 |
| 11-A02 | 精确版本、模型参数及平台能力均有来源，不支持组合在预检阻塞 |
| 11-A03 | 畸形/截断/无结束/非零退出样本不会被当成正常完整执行 |
| 11-A04 | 实际模型缺失或不符时保持执行门禁，不能用配置值填补证据 |
| 11-A05 | 原始记录与统一事件可互相定位，工具审计缺口不被适配器吞掉 |
| 11-A06 | 至少一组真实不同 CLI 的规划→审核→执行→验收链路通过 |
| 11-A07 | 已承诺目标平台上的真实入口、shell 需求、取消和环境锁经核验 |
| 11-A08 | unknown 用量、认证缺失、版本不兼容均有明确状态和恢复路径 |

本次未选择或调用第二 CLI；上述真实验证均为待实施项，离线 stub 通过不能替代它们。

## 8. 兼容与恢复

Pi 仍保留既有兼容入口和 v1 证据读取，新适配器失败不回写 Pi 历史记录。
版本不兼容时停止该 runtime 的新运行并提供明确原因，不能自动降级到另一模型。
回退时选择已获授权且能力足够的旧 profile，重新解析并按依赖范围重新审核。
中断调用按既有 collect/recover 流程取证，不能重试后隐藏原有失败和费用。
