流水线改为**七个端**：规划、合同、门禁、审核、执行五个端按顺序干活，协调人 womovie-c8（调度端）负责收发信件与每一次转交，决策端（JEV）可选，站主（你）最终拍板。CLI 与模型都不固定，画布里的绑定只是示例。画布上所有页面都已按七端改完；还没定的见「后续与待定」。

**界面上的新规则**

- **金色只给「上报给你」**：两种来源——规划端重拆后仍卡住；协调人遇到超出它权限的「需协调人决定」（放宽路径范围、改合同目标）时转交站主。两种样式相同，靠「来源」一列区分。Tab 栏计数胶囊、状态段圆点、总览 KPI 卡都数上报；审核中、打回中、提问信本身都不用金色。
- **信件**：工人一个回合 = 收信 → 干活并更新 `state.md` → 写 `report.md` → 交信给协调人 → 退出，不常驻。六种类型：交付 brand、返工完成 info、提问 warning、阻塞 danger、进度与交接 neutral。总览「最近的信件」只显示「摘要」；attempt 详情「信件」页签左列信、右显示原文（YAML 头 + 六个字段），纯文本。
- **合同概述**：就是合同端交付信的四个标准字段——摘要、验证、偏离、需协调人决定（不含提交与证据），先过筛查与 JEV，再由审核端一审核对与正文是否一致。
- **自述与意见**：合同概述、执行结果概述、信件正文都标「是自述」；JEV 判断、审核意见、规划端的上报原因标「是模型意见」，一律纯文本。
- **打回**：一审按责任退回合同端或门禁端；终审退回执行端，合同有缺陷时退回合同端；门禁战后不过直接打回执行端，不调 JEV、不进审核端。同一处连续打回超过 3 次上报规划端。合同生效、执行端开跑后才有 attempt，所以合同阶段的打回记在任务上，attempt 的「打回」只数门禁与终审。
- **工人状态与提交**：七端现况只写「休眠」（等信）或「本回合运行中」；attempt 页头显示「越权调用 N」和「提交 分支@sha」，提交只在本地分支；任务名后缀 `.vN` 是合同版本。
- **暂停迭代**：总览页头 \[暂停迭代…\]，预览 → 确认，当前一端跑完再停；断线时禁用。继续迭代只给可复制的命令。
- **总览**：本轮进度、本轮打回（按退回对象分）、上报给你（两种来源分开计）、本轮 token；「当前步骤」七步进度条、「本轮步骤」「七端现况」「最近的信件」。
- **任务列表**：筛选分组为合同阶段、执行阶段、已上报、已结项；attempt 表加「阶段 + 工人」「打回（门禁 · 终审）」「门禁」列；合同阶段的任务显示「还没有 attempt」。「下一步」不再给 `/review-pi` 这类命令。
- **attempt 详情**：页头下加七步进度条；页签：摘要 · 合同 · 基准测试 · 补丁 · 执行结果概述 · 门禁报告（含突变测试）· 审核 · 信件 · 事件 · 全部文件。
- **角色与模型**：七张角色卡（4 列），标题旁是工人名，卡内有「级别」；「流水线与规则」卡写了调度、基准测试、门禁不过、打回给谁、打回上限、上报站主、一个回合、工具禁令；决策端卡的 \[更改…\] 打开「配置决策端」对话框。
- **CLI 运行时**：已登记表的「现在由谁用」列出工人名；就绪检查按工人逐个列出，决策端缺凭据显示「跳过」（warning，不是 danger，因为它是可选端）。
- **凭据**：加 `ZHIPU_API_KEY`（contract-glm）；「决策模型」改为决策端 jev-judge；claude-code 的四个工人走登录，不读这些变量。
- **日志与用量**：用量按工人（7 行，含决策端调用次数）和按模型统计，注明统计范围（第 1–7 轮）；「按 attempt」只统计执行端。
- **首次启动**：加第 5 步「工人」；决策端缺凭据不影响进入。
- **组件库**：新增「七端组件」板：工人角色卡三种状态、七步进度条（进行中 / 被打回）、信件类型与信件行、信件原文、两种上报条目、工人状态 / 级别 / 打回计数等小标签。

## 字体与品牌

中英文统一用**等距更纱黑体 SC（Sarasa Mono SC，SIL OFL 1.1）**，并随应用打包；1 个汉字正好 2 个英文字符宽，表格、日志、补丁天然对齐。这推翻了文档 3.6「不打包字体文件」，但仍符合 0.2「不加载外部资源」：字体从应用包内同源加载。

### 字体

- **字体栈**：`"TT Sarasa Mono SC"`（随包）→ `"Sarasa Mono SC"` → `"等距更纱黑体 SC"` → `"Sarasa Term SC"` → `"Maple Mono NF CN"` → `"Cascadia Mono"` → `"Noto Sans Mono CJK SC"` → `monospace`。`--tt-font-sans` 与 `--tt-font-mono` 取同一条。
- **打包哪两个文件**：Regular 与 SemiBold。`@font-face` 字重范围写 300–500 → Regular、600–800 → SemiBold。更纱没有 Medium，500 的令牌按 Regular 显示，与画布一致。
- **来源与体积**：npm 包 `@fontpkg/sarasa-mono-sc` 0.36.0；完整 woff2 约 8.6 MB + 8.8 MB（TTF 各约 26 MB），安装包会明显变大。
- **画布里是子集**：只含本稿用到的字，画布里新加的生僻字可能显示为备用字体；应用必须用完整字体。
- **排版**：字号、行高沿用文档 3.6；根元素加 `font-variant-ligatures: none`；数字列仍写 `tabular-nums`。
- **许可**：OFL 要求随包附上版权声明与许可证文本，「设置 › 关于」的开源许可列表加上 Sarasa Gothic。

## 原型与文档的差异

交互阈值沿用文档第 7–8 节，本轮没有新定数值。可点击原型为了演示做了简化，以下几处**以文档为准**。

| 流程         | 原型里的做法                                                 | 实现时                                                       |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 写操作       | 预览固定 0.9 秒后返回，执行与退出码也是模拟的                | 按 8.3：等真实的预览与写路由返回，「已切换」只在重新读取后出现 |
| 断线重连     | 重试 3 次（1 / 2 / 4 秒）后出提示条，之后的等待写死为 8、16 秒 | 按 8.5：1 / 2 / 4 / 8 / 16 / 30 秒封顶，加 0–20% 随机延后，服务给出的重试时间是下限 |
| 就绪检查     | 每秒更新「已用 N 秒」，结局由画布右侧的选项决定（完成 / 失败 / 超时） | 按 8.4：每秒查一次 `GET /api/v1/jobs/<id>`，状态以服务返回为准 |
| 「上次更新」 | 写死的文字，如「3 秒前」「2 分钟前 · 可能已过期」            | 按 8.1 与 8.8 实时计算                                       |

### 4. 启动不闪白

缺省暗色后，启动时的白屏会很刺眼。建议 Electron 创建窗口时把背景色设为当前主题的 `--tt-bg`（暗 `#0C111A` / 亮 `#F3F5F9`），首帧画好再显示窗口。这一条画布里没有画。

## 画稿约定

画布里有些东西只是演示手段，不属于产品。

- **变体板不是独立设计**：浅色、深色 1024、骨架屏、空、出错、抽屉打开等板，都是同一个页面换参数引用的；改主稿就是改全部变体。
- **画布右侧的属性面板不是产品设置**：主题、页面状态、作业结局等只用来切换演示状态。
- **系统按钮是示意**：标题栏右端三个按钮（46 + 46 + 48 = 140）只是占位，实际由 Electron 的标题栏覆盖层绘制；macOS 左侧留 80 给红绿灯，画布里没有单独画 macOS 版。
- **数据是示例**：取自文档第 9 节，另补了少量演示用的行；各页之间的数字不保证对得上，实现时以接口返回为准。
- **「品牌标识」板是亮色底的规范板**，不随主题切换。
- **链接可点**：Tab 栏和页面里指向其他页面的链接，在画布里可以点击跳转。
