# 10 项目状态与恢复简报

状态：拟议实施说明，尚未实现；本文件不是已审核或可直接派遣的任务合同。
上位设计：[总设计](../code-kit-v2-design.md)第 8 节；导航：[实施索引](README.md)。
本模块对应 P5；状态投影基础可以提前建设，完整规划恢复须接入模块 09。

## 1. 目标与非目标

让主会话在恢复或切换上下文后，从持久记录取得当前目标、决定、进度、阻塞与下一动作。
进度事实由调度器登记，并能从原始证据重建；摘要仅帮助阅读，不成为验收依据。
在关键检查点提供有来源、有版本的简报，降低主模型重复读取日志的成本。

- 包含：项目事件索引、状态投影、决定索引、确定性简报、读取记录与恢复。
- 包含：按 `request_id` 汇总规划、执行、审阅工具和可选摘要的可观测用量。
- 不包含：常驻模型进程、自动理解任意历史聊天、自动批准或派遣任务。
- 不承诺：后台写入文件能唤醒任何主会话，或主模型永不遗漏规则。
- 不把摘要完整性、模型自述或进程退出成功当作任务已经验收。

## 2. 依赖与输入输出

基础依赖：[01 公共协议](01-baseline-and-protocols-审阅增强版.md)、[03 审核与锁定](03-approvals-and-locks-审阅增强版.md)、[07 工作流](07-workflows-and-scheduling-审阅增强版.md)。
完整接入：[09 规划与合同](09-planning-and-contracts.md)的草稿、审核和发布事件。
可选消费者：[13 Observer](13-optional-observer.md)；关闭它不影响本模块功能。

| 输入 | 使用方式 |
|---|---|
| 已完整落盘的 attempt、verdict、approval、合同记录 | 按稳定来源 ID 登记生命周期索引 |
| request 任务图、真实基线、候选引用和预算账本 | 投影当前状态，保留依赖等待与未完成项 |
| 主模型确认的目标、决定、适用规则 | 建立可追溯索引，不从执行器自述推导授权 |
| 已解析配置、插件锁和环境记录 | 说明状态对应的版本及其新鲜度 |

输出为 `.agent/project/` 中的事件索引、`state.json`、`brief.md` 和决定记录。
拟议 `project status` 输出结构化状态；`project brief` 输出受长度限制的简报及来源元数据。
所有新文件、命令与字段均需在实施合同中固定，本文件不创建这些运行产物。

## 3. 现状与复用点

`scripts/pi_dispatch.py::cmd_status` 已按 attempt 显示状态、检查、验收、时间和费用。
`cmd_metrics` 已区分 PASS 与例外接受，并明确现有统计只覆盖 Pi 执行端。
`cmd_mark` 维护 INTEGRATED、SUPERSEDED 等状态，保留集成引用和原因。
现有 `cmd_wait`、收集恢复、候选快照与 verdict 可作为项目事件的事实来源。

当前缺少跨任务依赖投影、版本化决定索引及恢复 brief，不能把 attempt 列表当成完整项目状态。
继续保留现有状态名和原始证据路径；新增索引不反向重写历史 attempt。
读取历史 attempt 时先看 `summary.md`，需要核实时再定位相关小段证据。

## 4. 接口和行为约束

### 4.1 存储与来源

| 路径 | 内容及责任 |
|---|---|
| `overview.md` | 目标、模块地图、约束；主模型审核后更新 |
| `decisions/` | 版本化决定、适用范围、用户来源及后继决定引用 |
| `events.jsonl` | 调度器追加的索引事件，不复制大段原始流 |
| `state.json` | 从有效事件和来源核验结果生成的可重建投影 |
| `brief.md` | 确定性生成的当前简报，带游标、来源版本和来源哈希 |
| `observer/` | 可选建议，与已确认事实分开 |

复用 `ResourceRef = {kind, id, sha256}`；文件引用另含仓库相对 `path`。
`sha256` 锁定具体 UTF-8 文件字节，不在本模块另造 JSON canonicalization 规则。
事件至少记录 schema、唯一事件 ID、递增游标、时间、`request_id`、类型和来源引用。
这里是项目生命周期索引，与模块 01/04 的厂商统一运行事件分开；二者通过来源关联，不互相冒充。
涉及任务、attempt、合同或审核时增加相应标识；来源引用有误就标为未核实。
稳定的来源记录 ID 用于补录去重；来源内容变化不能静默覆盖同 ID 的既有事实。

### 4.2 崩溃、并发与投影

写事件使用单写者锁，消费者按事件 ID 和来源记录 ID 去重，不能重复计费或重复完成。
投影用临时文件加原子替换，记录已应用游标；恢复只重放完整有效事件。
最后一条未完整写入的索引事件进入可诊断的恢复流程，不能解释成成功状态。
还必须扫描完整落盘但未被索引的 attempt 历史、verdict 和 approval，补齐缺失事件。
这一步覆盖“证据已写入、项目事件尚未追加”的双写崩溃窗口，不能只重放现有索引。
来源尚未完整落盘时标记待恢复；索引与来源冲突时暂停有关状态转换并报告。
索引损坏允许重建；原始 `.agent/runs/` 证据仍只读，不为修正投影修改历史。

### 4.3 简报、反馈与用量

简报按目标与非目标、规则索引、已确认决定、任务依赖、基线/候选、运行项、阻塞、预算和下一动作组织。
每项区分事实、假设、未核实或过期状态，附最小来源引用；截断必须明确提示省略内容。
刷新点覆盖会话恢复、规划审核、prepare/run、check/verdict/integration，以及失败或规则变化。
心跳只在进度变化或阻塞时生成增量提示；确定性 brief 不调用额外模型。
主会话检查点记录读取的 brief 哈希和事件游标；该记录不证明模型理解了全部规则。
brief 自身哈希由独立元数据或读取记录承载，不在文件正文内包含其自身哈希。
无宿主桥接能力时采用 pull；有明确接口后才接 host adapter，并报告实际投递结果。
不能将“文件生成成功”写成“主模型已收到”；不能将无关进度事件当成全部审核失效的原因。
相关规则、需求、合同、配置、基线或插件变化，按模块 03 的依赖绑定使对应审核失效。
预算继续以 `request_id` 为累计根，保留角色和调用来源，不因版本、重试或恢复清零。
投影读取模块 07 的预算账本，不对来源用量再次记账；规划外包也不等于总 token 自动减少。
当前主会话 token 或费用不可观测时写 `unknown`，不能声称已测得主模型节省比例。

## 6. 实施步骤

1. 固定来源记录 ID、事件类型、重复与冲突处理语义，建立含历史状态的最小夹具。
2. 实现登记、单写者锁与投影；先以确定性事件样本验证依赖、预算和状态不被重复推进。
3. 接入 attempt/verdict/approval 来源扫描，加入两种落盘顺序中断和恢复处理。
4. 实现状态与 brief 读取入口，提供长度限制、来源、过期标记及读取版本记录。
5. 接入模块 09 规划生命周期和技能检查点，验证新会话只依靠持久记录恢复。
6. 有实际宿主 API 时另做通知适配；没有 API 时交付明确的轮询读取操作说明。

## 7. 验收标准

| 编号 | 场景与通过条件 |
|---|---|
| 10-A01 | 相同事件或来源记录重复输入，完成次数和累计用量不增加 |
| 10-A02 | 投影写入中断后恢复，与不中断时的有效投影一致 |
| 10-A03 | 原始证据已落盘但索引未写入，重启能补录一次且仅一次 |
| 10-A04 | 未完整证据或冲突来源保留待恢复/阻塞，不推定 PASS 或集成 |
| 10-A05 | 删除可重建投影后，由持久来源恢复相同依赖、阻塞、基线和预算 |
| 10-A06 | brief 能逐条追溯事实，标明假设、未知用量、过期与截断项 |
| 10-A07 | 相关规则变化使对应审核失效；普通无关进度事件不会撤销审核 |
| 10-A08 | 无通知接口时显示 pull，关闭 observer 后所有确定性功能仍可用 |
| 10-A09 | 新会话恢复能正确区分待审、已验收、已集成及被后继结果替代的任务 |

上述为待实施验收项，本次文档拆分未运行其测试或生成运行证据。

## 8. 兼容与恢复

旧 attempt 缺少 v2 字段时保留 `unknown` 与来源年代，不补造当年的审核、模型或预算证据。
历史任务不得仅凭文字摘要自动归入某个 `request_id`；显式建立映射并记录来源。
回退新入口时保留项目记录供追溯，现有 status/metrics 仍按原语义读取旧数据。
损坏投影可重新生成；决定需要新版本纠正，不能覆盖旧版本来抹去前因。
