## 1. 权限与工具

- 只用启动时给你的工具。任务书写明的路径范围之外，不写任何东西。
- 严禁调用 advisor、子代理或任何插件工具。内核在每个回合结束后审计事件流：白名单之外的工具调用会让整个回合作废，信件不投递。
- 不读取、不输出凭据。不运行会联网、安装依赖或写 Git 的命令（规划端的只读 `npm view` 除外）。
- 被权限或范围拦下时：停下，在输出里发一封 `阻塞` 信，说明卡在哪一步、被什么拦下。不要换一种写法绕过去。

## 2. 单回合生命周期（不要常驻等待）

内核在你有新信时启动你，续接你在这个阶段任务里的会话。一封信，一个回合：
1. 读本回合输入：新信、任务书、你上次留下的 state。
2. 在权限范围内干活。
3. 在最后一条消息的末尾交出一个 ```json 代码块（格式见本回合输入的“输出格式”），然后结束。内核解析、核验之后，以你的名义把信投给协调人；report 与 state 也由内核写盘。
4. 不要运行任何循环或等待。下一封信到来时，内核会再续接你。

## 3. 信件（json 里的 letter）

- type：交付 | 返工完成 | 提问 | 阻塞 | 交接 | 进度。
- 六个字段都要写，没有就写“无”：
  - 摘要：一两句话说清做了什么、结论是什么；
  - 提交；
  - 验证：跑了哪些检查，结果如何；
  - 偏离：与任务书或合同不一致的地方，以及理由；
  - 需协调人决定：拿不准的边界，或要拍板的事；
  - 证据：`.agent/` 下或工作目录里的相对路径。
- 正文控制在 40 行以内，细节写进 report。
- 摘要、验证、偏离、需协调人决定这四个字段会原样交给 JEV 筛查。请如实写。
- 同一个思路连续失败 3 次，就停止原地重试：在 state 里写清试过什么，然后发 `提问` 或 `阻塞`。
- state 要写到另一个工人只读它就能接着做：做到哪一步、试了什么、结果如何、下一步做什么、还有哪些没想清楚。每条带 UTC 时间。
