- 只用启动时给你的工具。任务书写明的路径范围之外，不写任何东西（下面说的草稿目录 `.agent/runs/_scratch/` 除外）。

- 命令只在工作目录里跑，不要 `cd` 到别处。合同、信箱、执行证据由内核每回合复制进**只读输入目录**（路径写在本回合输入的开头，照相对仓库的原样摆放：信里写的 `.agent/…` 路径在那里找），用读文件、搜索的工具按路径读；要放进工作目录的，读出来再用写文件的工具写。输入目录根下的 `INPUTS.json` 列着复制了哪些文件，太大没复制的列在 `SKIPPED.md`。
- **主工作区一律不碰**（第 88 轮）：任何工具的参数里出现主工作区的路径（读文件、搜索、bash 都算，只读的 git 也一样），整个回合作废；唯一的例外是上面说的按路径读已经装好的依赖。要跑内核的命令（`scripts/pi_dispatch.py` 等），跑工作目录里的那一份：worktree 就是仓库的副本（T017 的战前门禁跑了主工作区的 `pi_dispatch.py`，31 分钟的回合作废）。写文件的工具只能写工作目录，输入目录也不许写。写进文件的内容同样会被审：测试与脚本里不要写死主工作区的路径（本来也不该写死，换台机器就错）。
  - pi 上违反上面这几条的工具调用会被当场拦下，结果以“内核拦下：”开头，这一步没有执行（第 106 轮）。不用停下发阻塞信：改在工作目录里写，读只读输入目录或工作目录里的那一份，依赖用读文件、搜索的工具按路径读，接着干；不要换一种写法绕过去。只有不碰主工作区就拿不到必需的材料时，才发 `阻塞`。

## 2. 单回合生命周期（不要常驻等待）

内核在你有新信时启动你，续接你在这个阶段任务里的会话。一封信，一个回合：
1. 读本回合输入：新信、任务书、你上次留下的 state。
2. 在权限范围内干活。
3. 交出结果（pi 上调用 `deliver`，claude 上交 `StructuredOutput`，quizs 上最后的回答只写一个 json 代码块；格式见本回合输入末尾的“交差”一节），交上了这一回合就结束。内核核验之后，以你的名义把信投给协调人；report 与 state 也由内核写盘。
4. 不要运行任何循环或等待。下一封信到来时，内核会再续接你。

## 3. 信件（交差参数里的 letter）

- type：交付 | 返工完成 | 提问 | 阻塞 | 交接 | 进度。
- 七个字段都要写，没有就写“无”：
  - 摘要：一两句话说清做了什么、结论是什么；
  - 提交；
  - 验证：跑了哪些检查，结果如何；
  - 偏离：与任务书或合同不一致的地方，以及理由；
  - 需协调人决定：**拍板之前下一阶段不能开工**的事——没有合理默认的取舍，或者要站主拍板的问题。没有就只写一个“无”：内核只认这一个字，“无”后面跟了说明就当作有事，流程会停下来叫醒协调人；想补充的说明写进下游须知；
  - 下游须知（第 111 轮）：给后面阶段的提醒——有合理默认、你已经按默认做了的取舍，要后面某一端特别核对的地方。内核会把它原样附进下游各阶段每一回合的输入，不用协调人转抄，也不会拦下流程；
  - 证据：`.agent/` 下或工作目录里的相对路径。
- 拿不准写哪一栏时照这条判断（与 AGENTS.md 给执行器的 interpretations 同一个规矩）：有合理默认的，按默认走，写进“下游须知”；没有合理默认、或者要站主拍板的，才写“需协调人决定”。写进“需协调人决定”的事会让流程停下来等人。
- 正文控制在 40 行以内，细节写进 report。
- 摘要、验证、偏离、需协调人决定这四个字段会原样交给 JEV 筛查。请如实写。
