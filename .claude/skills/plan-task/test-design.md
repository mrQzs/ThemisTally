# 让测试只针对受测规则

适用于输入校验、权限、摘要与版本兼容任务。先把下面的设计写进合同，再由 Pi 实现；验收端按同一设计做最小变异。已有充分覆盖时复用，不机械地增加用例数。

## 反例从合法输入出发

每个拒绝反例需要三个要素：已经通过验证的合法基线、唯一受测变化、具体错误码或可观察结果。

例如用途授权与状态门槛独立。测试“candidate 请求 production”能保护状态规则，却不能单独保护用途授权：去掉用途判断，状态仍会拒绝。用途反例应选择状态本来允许、但 enrollment 没有授权的用途；再证明授权该用途后同一输入会通过。

检查失败日志：如果删掉目标守卫后测试只是撞上另一条校验，不要据此宣称目标行为得到完整验证。收集失败、语法错误和导入失败也不能算有效变异证据。

特别留意相同错误码的多个守卫。例如验证映射表多了一项时，额外项同时指向不存在的目标，会被“集合不精确”和“目标不存在”两条守卫拒绝；删除前者，测试仍绿。应使用确实存在、且没有被其他项占用的目标，仅让源集合多一项；缺目标另做自己的反例。

“唯一变化”指唯一不满足的规则，不是机械地只改一个字段。例如authority必须同时匹配kind和subject basis，只翻authority会同时违反两条规则，哪怕精确断言错误码也可能漏检。要测authority/kind，应把basis及关联摘要调整为该authority的合法组合，单独留下kind归属错误。共享ID一致性也应在没有“必须选候选表内目标”这一额外守卫的合法分支测试，否则两个同码守卫会互相遮蔽。

## 分支与类型逐项隔离

| 规则类型 | 需要的输入对 | 常见漏检 |
| --- | --- | --- |
| 可选对象 | null 合法；合法非空对象逐字段变化 | 只有 null，非空字段从摘要删除仍通过 |
| complete / partial 等分支 | 各分支自己的合法基线和边界 | partial 反例先违反 complete 专属规则 |
| 数值范围 | 相等、合法拓宽、上下界分别缩窄 | 一次改多个边界，部分守卫缺失不可见 |
| 多种值类型 | 合同点名的每种类型；无关字段故意不同的正例 | 只测 text，漏掉各类引用；无关字段两侧相同 |
| 有限枚举 | 有效源值、不可达源值、目标集合和长度分别变化 | 集合测试掩盖长度；空值过滤掩盖长度过滤 |
| 值保留 / 显式适配 | 每个要求保留的非默认值；非空关联；实际执行模式 | 默认值正例全绿，却漏掉holder变null、possible变asserted、replay回执写fake |
| 解析 | 合法文档仅插入重复键、未知字段或非法值；顶层与嵌套分别测试 | 空数组本来非法，反例不能隔离解析规则 |
| 多个参数共用一条类型规则 | 每个参数各自的反例：与合法值相等的子类、不可哈希的值 | 只给一个参数测不可哈希的值；其余参数先查字典再查类型，冒出 `TypeError` |

精确类型（`type(x) is str`）与 `isinstance` 只有与合法值相等的子类才分辨得出，例如 `class S(str)` 或 `StrEnum` 成员；`None`、`5` 在两种写法下都会被拒绝。不可哈希的值（list）能抓住“查字典之前没有检查类型”。KitExperiment 实机：调度器合同写了“不可哈希的值也报表中的 code”，但 oracle 只对 operation id 用了 list，`observe` 先用 dimension 查字典，冒出 `TypeError`；合同让执行器测 `None`、`5`，执行器测试单独只抓住 36 个变异中的 4 个。

“无关字段不同”也要分别激活每个错误分支：若非整数源区间为1000..2000、目标为0..10，只能识别错误的上界比较；使用-1000..2000才能同时覆盖错误下界比较。有限枚举还需要合法正例：所有可达标签都适配目标长度时，源长度上限可以大于目标，不能按无限字符串值域直接比较两个cap。

断言应放在合同约束的那一层。原图要求固定角色顺序时，检查已自动排序的manifest不能保护原图；frame.modality保留也不能替代candidate.modality保留。合同应明确哪些原始字段和哪些规范产物各自需要证据，避免只断言最终非空或派生结果。

夹具名称不能代替实际差异。声称“source与view可以不同”的正例，应检查两者确实不同且各自有效；若两者仍来自同一文本，错误地比较source也会通过。串联多个校验器时，先根据失败栈确认最早失败的调用与输入；上游缺少mention造成的类型表为空，不能靠反复验证下游已正确的实体Pin来定位。

长度与格式是不同约束：格式反例保持合法长度，仅破坏前缀、字符集或版本位。字符长度涉及Unicode时，BMP汉字只能区分码点与UTF-8字节，不能区分码点与UTF-16单元；补非BMP字符。顺序遍历还需至少三项来检验前驱是否更新，链中间摘要反例应同步修正下一项父引用，避免父链错误掩盖摘要遗漏。

## 摘要要保护具体字段

- 固定其他字段，分别改变 tenant、scope、用途、子集、版本或关联摘要。两个完全不同的对象摘要不同，不能证明其中每个字段都参与摘要。
- 排序不影响语义时，各集合分别逆序；不要一次同时逆序多个集合掩盖遗漏。
- 要求保留原数组顺序时，用多项输入直接比较完整expected列表。仅断言两种输入摘要不同，无法识别实现把每份输入都反转的错误；数组仍有区分度，但输出顺序已经错了。
- 两字段必须一起变化才能合法时，用独立手工完整投影或固定黄金值确认摘要；仅断言摘要改变，会被仍参与摘要的另一个字段掩盖。
- 完整投影含某键，不等于证明其非空值被保留。人工记录里校准/阈值全是null时，再补一份这些值非空的合法自动记录；把非空值错误清空的故障也必须被发现。
- 预期摘要不能调用被测摘要属性或照搬同一个动态投影算法。使用项目既有规范向量或独立编码与域帧计算。
- 合同要求关联链时，使用真实模型链，如 enrollment → binding → unit；不要把前一层摘要冒充后一层输入。纯模型证据与数据库权限、复用、真实批准分别验收。

## 合同中的最小证据表

只为本任务受影响的规则填写。用规则 ID 引用行为，不再重写另一套语义。

| 规则 ID | 合法基线 / 唯一变化 | 预期结果 | 最小变异 / 预期失败用例 |
| --- | --- | --- | --- |
| B01 | 状态允许的用途；仅撤掉 enrollment 授权 | 指定拒绝码 | 去掉用途判断；该反例不再抛错 |

如果写不出可以独立观察的差异，先查清验证顺序或设计，不把模糊要求直接交给执行器。变异默认由复审端在固定候选上运行；执行器只有在合同明确列出变异命令和目标范围时才运行。local_test不自动授权额外变异；临时修改后恢复也不能突破Scope。正常测试输入变体不属于这里“故意改坏实现”的变异。

先判断规则是否能独立违反。例如 corrections 的原键必须唯一且属于至多16个 evidence，那么17个合法独立 correction 不可能同时满足其他条件；正长度 quote 与 end-start==len(quote) 也已蕴含 start<end。此时不要为“唯一变化”编造不可能的合法基线，或把等价守卫删除称为漏检漏洞。若合同还要求字段级 too_long、missing 等错误位置/类型或导出的 Schema 上限，明确把它们作为这一层的可观察结果单独验证；最终接受集合、错误协议和 Schema 不是同一个结论。

等价判断必须注明入口。某子DTO的Hash字段在外层受到“必须属于Hash集合”保护，不代表这个公开子DTO独立验证时也有该保护；分别检查所有声明支持的入口，不把外层guard当作子DTO类型约束的替代品。

闭合 DTO 任务不要只写“各模型覆盖合法边界和非法值”。把本次新增的约束列成简短矩阵：模型/字段、合法最小值与最大值、刚越界值、预期错误位置及类型。共享基类的既有行为不必全量重测，但新模型是否正确继承、字段是否仍必需、标量类型与集合上限是否接对，需要可观察的具体证据。参数化测试可合并重复构造，不能只以一个普通正例代表所有边界。需要完整图才能到达某条守卫时，合法基线也要明确；例如集合至少一项，测试映射缺项就从两项开始删一项，避免先撞上 DTO 长度守卫。

必填但允许null的字段，应从允许null的分支删除该字段并断言missing错误位置；从必须非null的分支删除它，再捕获任意ValidationError，会把后续业务错误当成required证据。继承的metadata逐字段删除，不能一次漏三个字段声称分别验证。必需字段清单来自独立fixture/合同，不按被测模型的is_required筛选；否则实现意外增加默认值，测试也会随之跳过。目标是JSON输入时，至少让矩阵经过真实JSON验证入口，不用Python专有tuple形状替代协议证明。

“经过JSON入口”同时需要合法正例和对应反例。仅有子DTO的JSON缺字段测试，不能证明顶层封装能接收合法JSON；即使顶层完全拒绝JSON，全部Python字典测试仍可能通过。用独立JSON fixture逐模型验证合法输入，再只删字段/增extra；Python构造测试可保留，但不替代协议入口。序列化非法输入时也要确认失败来自DTO：项目JCS若先拒绝浮点数，不能把这个异常当成整数字段的类型校验证据。

数据库列默认值与DTO字段是否可省略分别写明。例如“数据库初值0；提交DTO必须显式提供，未设置DTO默认值”，避免执行器把存储层事实误读为输入规则，反复重新裁定已经确定的设计。

未逐项列明的细分覆盖，在首次验收发现时记为规划补充；合同已明确要求的边界没有测试，才归执行遗漏。不能在验收时临时把所有变异都变成原合同的完成条件，也不能用测试总数代替规则证据。

测试返工要逐条对照上一轮缺口，确认每个目标反例现在能独立观察错误。“保留有效断言”允许原地修正多重错误输入、收紧弱断言，不等于只能追加代码；新增很多用例、零删除，也不能证明旧的遮蔽问题已经消失。

兼容性反例应使用仓库实际旧版本标识，不凭命名规律猜测；例如真实旧值是`extraction-candidates-v1`，测试另一个不存在的`extraction-candidates/1`不能保护旧格式隔离。唯一性规则要说明范围：要求跨集合全局唯一时，同一集合重复与跨集合重复分开验证。

Validation commands通常是必须完成的最小检查集，不必写成穷举命令白名单。同一文件的测试子集、无额外文件的类型诊断可在local_test授权内明确允许；需要禁止的是具体越界操作、无关套件和未经合同列明的产品故障注入。把时间安排建议写成绝对禁止，会制造与行为质量无关的流程偏差。验收应如实保留偏差，并区分其是否影响实际范围、行为或证据，不能追溯改写冻结合同。

必要检查优先直接运行并读取工具输出。`pytest ... | tail` 后的 `$?` 默认是 tail 的退出码，不能据此报告 pytest 成功；若确需管道，应在支持的 shell 中启用 `pipefail` 并保留真实失败状态。工具显示 `isError=false` 也不能证明复合命令里的每条检查成功。验收仍以调度器在固定候选上的独立 argv 检查为准。
