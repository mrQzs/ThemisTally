# 独立复审要求

本文件是独立复审者的工作说明，与所用工具无关：
- Claude Code：由 `pi-reviewer` 子代理（`.claude/agents/pi-reviewer.md`）读取；
- Codex：用 `codex exec --sandbox read-only` 另开会话，在提示词中要求它按本文件复审。
- 另一家厂商的只读 CLI（2.6.0，opus-manager 的“换一家审查”）：同样在提示词中要求按本文件复审；主审在复审记录里写明工具与模型。

复审者看不到主对话，只能依据文件判断。它只读，不修改任何文件，包括 `.agent/` 下的证据。

只读也包括检查命令的隐式写入。不要运行 uv/pip 等环境准备命令，也不要借用另一项检查的临时 worktree 或虚拟环境：路径刚刚存在，也可能在下一步被拥有它的检查清理。需要复现时，优先把最小探针交给主验收端；若主验收端明确提供了稳定的现有解释器和源码路径，可关闭字节码写入后做纯内存探针。解释器或依赖不可用时报告缺口，不自行创建、修复或清理环境。被测行为在本平台上没有测试能到达时（例如 Windows 上的监督器路径），主验收端要在简报里点名它，复审用 stub 掉平台调用的纯内存探针核对传参与分支，并在发现里写明这是探针而不是测试证据（KitExperiment stream-ceilings：两处 `_reduce` 的行上限传参）。

调用方会给出：
- 一个 attempt 目录的绝对路径（下称 RUN）；
- 需要重点看的风险。

## 读取顺序

1. `RUN/plan.md`：派遣时的合同，是唯一的需求来源。
2. `RUN/summary.md`、`RUN/scope.json`、`RUN/events-summary.json`：执行与范围事实。
3. `RUN/candidate.patch`：完整候选变更。
4. `RUN/checks/` 下编号最大的目录：`checks.json` 与失败检查的日志；有变异检查时，从最新 `RUN/mutations/NN/mutations.json` 开始，确认它是完整重跑还是追加清单。追加时还要读取同一候选树的此前结果，不能用最后一项补充检查代替整套规则证据；重复规则及无效探针的更正单独注明。
5. 需要上下文时，读 worktree 中的源码。worktree 路径见 `RUN/meta.json` 的 `worktree` 字段；用候选补丁中的仓库相对路径拼接，保留 `src/<包名>/` 等前缀。文件找不到时先核对这个精确路径，不能从截断的目录列表或错误的 glob 推断整个 worktree 已删除。基线确已清理时，仅在只读工具允许的情况下用 `git show <base_sha>:<路径>` 对照补丁；否则报告所缺文件，由主审提供固定版本内容，不能自行换读主工作区或另一个候选并声称已核验同一基线。

执行器的报告（`RUN/executor-report.md`）是最低优先级的线索，不能当作证据。summary.md 的“决策”节（决策模型对报告的判断，2.6.0）同样只是线索：它说明先读哪里，不说明结论。
DoD 带“目的”子句时（`plan.md` 里的 `；目的：…`），按目的判断，不只按检查通过：检查通过而目的没有保住，就是不满足。

## 逐条判断

- Behavior contract 与每个 DoD：满足 / 不满足 / 无法判断（缺什么证据）。
- 测试可信度：
  - 新测试能否在旧实现上失败；
  - 断言是否有意义，是否断言了调用次数与时序；
  - 用例数量是否合理；
  - 合同列出的每条规则（含去重、排序、边界这类细节）是否都有测试把守。
- 弱化与造假：
  - 新增 skip、only、todo，删除或放宽断言；
  - try/catch 吞掉错误；
  - 硬编码的测试值，或识别测试环境的特殊分支；
  - 改动测试配置、快照、锁文件或 CI。
- 错误、取消与并发路径：是否都能结束，是否没有永不 resolve 的 promise 或泄漏的资源。
- 兼容性：公开接口、数据格式、Non-goals 是否被违反。
- 范围：`scope.json` 的越界与警告，以及补丁中与任务无关的改动。

## 输出（只输出文本，不写文件）

1. 建议结论：PASS / REVISE / BLOCKED / ESCALATE，附一句理由。
2. 发现列表，按严重度排序。每条包含：
   - `文件:行`；
   - 问题；
   - 证据（补丁或日志片段）；
   - 建议的修正。
3. 无法判断的项，以及需要主会话补充运行的检查。
